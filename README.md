# Stock Keeper Docs & Test

> AI 에이전트와 함께하는 **지능형 문서 관리 및 프로토타입 테스트** 레포지토리

---

## 📋 소개

이 레포지토리는 **AI 기반의 PRD(요구사항 정의서) 관리 시스템**과 **UI 프로토타입**을 통합하여 효율적인 개발 프로세스를 지원합니다.
에이전틱 워크플로우(Agentic Workflow)를 통해 요구사항 분석부터 명세서 반영, 검증까지의 과정을 자동화하고 표준화합니다.

---

## 🤖 AI 에이전트 & 워크플로우

이 프로젝트는 다음과 같은 에이전틱 워크플로우를 통해 문서를 관리합니다.

### 🛠️ 슬래시 커맨드 (Slash Commands)

| 커맨드              | 설명                                                                                                                 | 사용 시점                        |
| ------------------- | -------------------------------------------------------------------------------------------------------------------- | -------------------------------- |
| `/prd-prepare`    | **[Inbox -> Staging]**`<br>` `_inbox`의 요구사항을 분석하여 구조화된 PRD 초안을 `_staging`에 생성합니다. | 새로운 요구사항이 있을 때        |
| `/prd-validate`   | **[Validate Staging/Specs]**`<br>` 작성된 PRD의 정합성, 중복, 누락 여부를 검증합니다.                        | 초안 검토 또는 전체 스펙 점검 시 |
| `/prd-process`    | **[Staging -> Specs]**`<br>` 승인된 `_staging`의 내용을 최종 `specs` 문서에 반영하고 아카이빙합니다.     | 초안 승인 후                     |
| `/prd-sync-tasks` | **[Specs -> Tasks]**`<br>` 변경된 스펙 사항을 `tasks` 목록에 동기화합니다.                                 | 스펙 확정 후 할 일 생성 시       |
| `/commit`         | **[Conventional Commit]**`<br>` 변경 사항을 분석하여 표준화된 커밋 메시지로 커밋합니다.                      | 작업 완료 후                     |

### 🧠 전문 스킬 (Skills)

* **prd-architect**: PRD 구조 설계, 의존성 분석, 정합성 검증을 수행하는 전문 스킬입니다.

---

## 🚀 사용 가이드 (Workflow Cycle)

1. **요구사항 등록 (`_inbox`)**: 새로운 기능이나 수정 요청을 `Docs/AI_PRD/_inbox/`에 자유로운 형식(메모, 텍스트 등)으로 저장합니다.
2. **초안 작성 (`/prd-prepare`)**: 에이전트에게 `/prd-prepare`를 요청하여 구조화된 초안을 생성합니다.
3. **검토 및 수정**: `Docs/AI_PRD/_staging/`에 생성된 문서를 검토하고, 필요시 `/prd-validate`로 검증합니다.
4. **최종 반영 (`/prd-process`)**: 내용이 확정되면 `/prd-process`를 실행하여 `specs` 폴더의 산출물(DB, API, UI 등)에 반영합니다.
5. **작업 동기화 (`/prd-sync-tasks`)**: 반영된 스펙을 바탕으로 구현 할 일을 생성합니다.

---

## 👥 문서 관리 규칙

* **Specs (명세서)**: `Docs/AI_PRD/specs/` 내의 문서는 **Single Source of Truth**입니다. 임의로 수정하지 않고 워크플로우를 통해 업데이트합니다.
* **Staging (대기소)**: `_staging` 폴더는 임시 공간이므로, 반영(`process`) 후에는 자동으로 정리됩니다.
